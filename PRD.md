# PRD — «Рейс»: личный планировщик путешествий

| | |
|---|---|

| **Версия документа** | 1.0 |
| **Дата** | 13 ноября 2026 |
| **Статус** | Реализован MVP, опубликован как артефакт |

---

## 1. Обзор

«Рейс» — это личный кабинет путешественника, в котором один пользователь ведёт все свои поездки от идеи до чемодана. Приложение объединяет AI-помощника, планировщик поездок, подбор направлений, расчёт бюджета, маршрут по дням, поиск отелей и билетов, списки вещей и климатическую справку по направлениям — в одном интерфейсе.

Продукт реализован как автономная веб-страница: не требует сервера и бэкенда, все данные хранятся локально в браузере пользователя. AI-помощник подключается через runtime-возможность платформы (`sample`).

### Метафора продукта
Интерфейс выстроен вокруг образа путешествия: «посадочный талон» ближайшей поездки с обратным отсчётом как главный акцент, палитра сумеречного неба над горизонтом, тёплый янтарный акцент (огни города / закат) и аквамарин (море).

---

## 2. Проблема и цели

### Проблема
Планирование поездки разбросано по десяткам вкладок и приложений: заметки, таблицы для бюджета, сайты авиакомпаний, агрегаторы отелей, прогнозы погоды, чек-листы. Нет единого места, где поездка живёт целиком и где можно быстро спросить совета.

### Цели продукта
- Дать одно место для всех деталей поездки.
- Снизить порог входа: от «хочу куда-нибудь поехать» до готового плана за несколько минут.
- Встроить AI-советника, который знает контекст поездок пользователя.
- Работать офлайн для всего, кроме AI-чата и живых прогнозов.

### Критерии успеха (для личного использования)
- Пользователь ведёт в приложении ≥1 реальную поездку целиком (даты, бюджет, маршрут, вещи).
- Разделы заполняются без обращения к сторонним инструментам, кроме финальной брони.
- AI-помощник даёт применимые ответы с учётом сохранённых поездок.

---

## 3. Целевой пользователь

**Основной (и единственный) пользователь** — владелец приложения, самостоятельно планирующий личные поездки. Проживает в Казахстане (используется для визовых пометок и советов по умолчанию). Русскоязычный интерфейс.

Сценарии:
- Планирует отпуск заранее и хочет видеть обратный отсчёт и собранный план.
- Выбирает направление по сезону и бюджету.
- Собирает список вещей под тип поездки.
- Быстро переходит к поиску билетов и жилья с уже подставленными городом и датами.

---

## 4. Объём (Scope)

### Входит в MVP
Девять разделов: Обзор, AI-помощник, Поездки, Направления, Бюджет, Маршрут, Отели и билеты, Список вещей, Погода. Локальное хранение, светлая/тёмная тема, адаптив.

### Не входит в MVP (вынесено в раздел 10)
Аккаунты и синхронизация между устройствами, живой прогноз погоды, реальная агрегация цен внутри приложения, бронирование и оплата, мультивалютный пересчёт, экспорт в PDF, совместный доступ.

## 5. Функциональные требования

Требования сгруппированы по разделам. ID вида `R-<раздел>-<номер>`.

### 5.1 Обзор (Dashboard)
- `R-OBZ-1` Приветствие по времени суток и имени пользователя (если задано).
- `R-OBZ-2` «Посадочный талон» ближайшей предстоящей поездки: город, страна, флаг-значок, даты, число путешественников, бюджет и обратный отсчёт до вылета в днях.
- `R-OBZ-3` Если поездок нет — пустое состояние с призывом создать первую поездку.
- `R-OBZ-4` Блок статистики: число поездок, число уникальных стран, суммарный бюджет.
- `R-OBZ-5` Быстрые действия: спросить AI, новая поездка, выбрать направление, рассчитать бюджет.
- `R-OBZ-6` Список ближайших поездок (до 4) с переходом к редактированию.

### 5.2 AI-помощник
- `R-AI-1` Чат-интерфейс с историей сообщений в рамках сессии.
- `R-AI-2` Помощнику в контекст передаются все сохранённые поездки (название, город, страна, даты, число людей, бюджет).
- `R-AI-3` Системная инструкция: тёплый русскоязычный помощник по путешествиям; подбор направлений, маршруты по дням, бюджет, сезон/погода, список вещей, советы по жилью и перелётам; не выдумывать точные цены и расписания; пользователь из Казахстана по умолчанию.
- `R-AI-4` Быстрые подсказки-чипы, зависящие от наличия активной поездки.
- `R-AI-5` Потоковый вывод ответа (обновление по мере генерации), индикатор «думает».
- `R-AI-6` Корректная деградация: если возможность AI недоступна (предпросмотр / внешний доступ / отказ) — понятное сообщение, остальные разделы продолжают работать.
- `R-AI-7` Обработка ошибок: лимит запросов, прочие сбои — человекочитаемые тексты.

### 5.3 Поездки
- `R-TRIP-1` Создание поездки: название, страна, город, значок-эмодзи, даты начала и конца, число путешественников, валюта бюджета, заметки.
- `R-TRIP-2` Редактирование и удаление поездки (удаление с подтверждением).
- `R-TRIP-3` Выбор «активной» поездки; активная поездка используется в разделах Бюджет, Маршрут, Поиск, Вещи.
- `R-TRIP-4` Статус поездки вычисляется из дат: черновик / через N дней / сейчас в поездке / завершена.
- `R-TRIP-5` Карточки поездок с баннером, статусом, датами, числом людей и бюджетом.

### 5.4 Направления
- `R-DEST-1` Каталог из 27 популярных стран (см. Приложение A), с учётом частых направлений для русскоязычного пользователя.
- `R-DEST-2` По каждому направлению: страна, главный город, регион, лучший сезон, валюта, визовая пометка (для РК), средняя дневная/ночная температура текущего месяца, краткое описание.
- `R-DEST-3` Фильтр по регионам.
- `R-DEST-4` Действие «В поездку» — создание поездки с предзаполненными страной/городом.
- `R-DEST-5` Действие «Погода» — переход в раздел погоды по этому направлению.

### 5.5 Бюджет
- `R-BUD-1` Шесть категорий расходов: перелёт, жильё, еда, транспорт, активности, прочее.
- `R-BUD-2` Ввод сумм по категориям для активной поездки; автоматический подсчёт итога.
- `R-BUD-3` Производные показатели: на человека, в день, на человека в день (день вычисляется из диапазона дат).
- `R-BUD-4` Диаграмма распределения расходов по категориям.
- `R-BUD-5` Живое обновление итогов без потери фокуса в полях ввода.
- `R-BUD-6` Подсказка о резерве 10–15% и переход к обсуждению бюджета с AI.

### 5.6 Маршрут (по дням)
- `R-RTE-1` Построение плана по дням для активной поездки.
- `R-RTE-2` Добавление/удаление дней; заголовок дня; добавление/удаление пунктов внутри дня.
- `R-RTE-3` Пустое состояние с возможностью сгенерировать план через AI.

### 5.7 Отели и билеты
- `R-SRCH-1` Готовые ссылки на внешние сервисы с подстановкой города и дат активной поездки:
  - Авиабилеты: Google Flights, Skyscanner, Aviasales.
  - Жильё: Booking.com, Airbnb, Островок.
  - Впечатления: GetYourGuide.
- `R-SRCH-2` Ручной ввод города, если активная поездка не выбрана.
- `R-SRCH-3` Все ссылки открываются в новой вкладке; приложение не бронирует и не оплачивает — явное предупреждение об этом.

### 5.8 Список вещей
- `R-PACK-1` Чек-лист вещей для активной поездки, сгруппированный по категориям.
- `R-PACK-2` Готовые наборы-шаблоны: базовый, пляж, город, зима/горы, трекинг (добавляются без дублей).
- `R-PACK-3` Добавление своих пунктов, отметка «собрано», удаление, «убрать собранное».
- `R-PACK-4` Прогресс сборов (собрано X из Y).

### 5.9 Погода
- `R-WTR-1` По каждому направлению — средние дневные/ночные температуры по месяцам (климатическая норма).
- `R-WTR-2` Визуализация 12 месяцев столбиками с подсветкой текущего месяца.
- `R-WTR-3` Карточка выбранного направления: «сейчас в среднем», лучший сезон, краткое описание.
- `R-WTR-4` Сетка всех направлений с температурой текущего месяца и быстрым переключением.
- `R-WTR-5` Явная пометка, что это климатическая норма, а не прогноз; отсылка к сервисам погоды для точного прогноза.

## 6. Нефункциональные требования

- `NF-1 Автономность.` Единый self-contained HTML-файл; без внешних зависимостей, кроме шрифтов Google Fonts. Без сборки и сервера.
- `NF-2 Хранение.` Все пользовательские данные — в `localStorage` браузера; приватны для устройства и браузера. Запись обёрнута в try/catch, корректная работа при пустом хранилище.
- `NF-3 Тема.` Светлая/тёмная/системная; токены цвета на `:root` с переопределением под `prefers-color-scheme` и явные режимы. Переключатель сохраняется.
- `NF-4 Адаптив.` Полноценная работа на мобильном: боковое меню превращается в выдвижную панель, учёт safe-area (вырезы, системные панели).
- `NF-5 Доступность.` Видимый фокус, уважение `prefers-reduced-motion`, читаемый контраст, осмысленные пустые состояния и тексты ошибок.
- `NF-6 Производительность.` Мгновенный отклик интерфейса (локальный рендер); потоковый вывод AI.
- `NF-7 Язык.` Весь интерфейс и ответы помощника — на русском.
- `NF-8 Локаль.` Форматирование чисел и валют под русскую локаль; визовые пометки и советы по умолчанию для Казахстана.

## 7. Техническая архитектура и ограничения

### 7.1 Структура
- Один HTML-файл: встроенные стили (CSS-переменные как дизайн-токены) и ванильный JavaScript без фреймворков.
- Внутренняя навигация — переключение разделов (SPA-подобно), без перезагрузки.
- Данные — объект состояния, сериализуемый в `localStorage` (ключ `reys_travel_v1`).

### 7.2 AI-помощник
- Подключается через платформенную возможность `sample` (запрос к Claude из опубликованной страницы).
- Память отсутствует между вызовами — при каждом запросе передаётся системная инструкция, контекст поездок и вся история диалога.
- Доступен в опубликованном приложении внутри аккаунта владельца; в предпросмотре и по внешней ссылке может быть недоступен — предусмотрена деградация.

### 7.3 Ключевое ограничение по погоде
Опубликованная страница не может обращаться к внешнему API погоды (политика безопасности площадки блокирует сторонние сетевые запросы). Поэтому:
- В MVP погода реализована как **климатические нормы** (исторические средние по месяцам), зашитые в данные направлений — это надёжно и достаточно для выбора сезона.
- Для прогноза на конкретные даты пользователь направляется к внешнему сервису погоды.
- Живой прогноз возможен только при другом способе запуска приложения (не как публичная ссылка) — вынесено в будущие доработки.

### 7.4 Поиск билетов и жилья
Приложение не агрегирует цены и не бронирует. Оно формирует готовые deep-ссылки на внешние сервисы с подставленными городом, датами и числом гостей. Любая бронь и оплата — на стороне пользователя на сайте партнёра.

## 8. Модель данных

```
state = {
  profile: { name: string },
  activeTripId: string | null,
  theme: 'system' | 'light' | 'dark',
  trips: [
    {
      id: string,
      title: string,
      country: string,
      city: string,
      flag: string,            // эмодзи-значок
      startDate: string,       // YYYY-MM-DD
      endDate: string,
      travelers: number,
      currency: 'USD'|'EUR'|'KZT'|'RUB'|'TRY'|'THB'|'GBP',
      budget: { flights, lodging, food, transport, activities, misc }, // числа
      itinerary: [ { title: string, items: string[] } ],   // дни
      packing:   [ { id, label, cat, done } ],
      notes: string
    }
  ]
}
```

Справочник направлений (`DESTINATIONS`) — статические данные: страна, город, флаг, регион, валюта, язык, лучший сезон, виза, массивы средних дневных/ночных температур по 12 месяцам, краткое описание.

## 9. Дизайн-система

### Палитра (образ «сумеречный горизонт»)
- Фон (светлая): прохладный воздушный `#eef1f7`; поверхность `#ffffff`.
- Фон (тёмная): глубокий сумеречный синий `#0d1220`; поверхность `#161f32`.
- Янтарный акцент (огни/закат): `#e4852a` / `#f0a33c` в тёмной теме.
- Аквамарин (море): `#12988a` / `#35c2ac`.
- Коралловый — для предупреждений и обратного отсчёта.
- Градиент «посадочного талона»: от ночного индиго через сумерки к закатному оранжевому.

### Типографика
- Заголовки: Bricolage Grotesque (характерный современный гротеск).
- Текст и интерфейс: Inter Tight.
- Числа — табличные, для бюджета и температур.

### Акцент
Основная «смелость» интерфейса сосредоточена в одном месте — «посадочном талоне» ближайшей поездки с перфорацией и обратным отсчётом; остальное оформление сдержанное.

## 10. Будущие доработки (вне MVP)

- `F-1` Живой прогноз погоды на конкретные даты (при запуске, допускающем внешние запросы).
- `F-2` AI-помощник, создающий поездки и маршруты напрямую из чата (инструменты/actions).
- `F-3` Мультивалютный пересчёт бюджета по курсу.
- `F-4` Экспорт поездки в PDF (и/или печатная версия маршрута).
- `F-5` Синхронизация между устройствами и резервная копия.
- `F-6` Совместный доступ к поездке (попутчики).
- `F-7` Напоминания: виза, регистрация на рейс, сборы.
- `F-8` Расширение каталога направлений и добавление городов внутри стран.

## 11. Риски и открытые вопросы

| Риск / вопрос | Комментарий |
|---|---|
| Погода — норма, а не прогноз | Явно помечено в UI; при необходимости — доработка F-1 |
| AI недоступен вне аккаунта | Предусмотрена деградация; критично только при шеринге |
| Данные только локально | Удобно и приватно, но нет бэкапа — решается F-5 |
| Визовые пометки устаревают | Это ориентир для РК, не юридический факт; проверять перед поездкой |
| Deep-ссылки партнёров могут меняться | Периодически проверять формат URL сервисов |
